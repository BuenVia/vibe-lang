# Roadmap: next learning features

Designs for features that build on **Fill the gap** (the `Sentence` resource), which was step 1 of the plan.
Sections 1–4 below are steps 2–4 of that plan, with step 4 split into the translation mode and the mistakes log.
Each section can be picked up in its own session. The aim of all of them:

- **A. Understanding in context.** Practise words and grammar inside sentences, not as isolated terms.
- **B. Near-instant recall.** Being able to produce the form quickly enough to use it while speaking or writing.

No AI or paid APIs: everything runs on the server's own logic or on free on-device/browser features.

| # | Feature | Main goal | Depends on |
|---|---|---|---|
| 1 | Spaced repetition with a speed rule | B | — (works better once 3 and 4 exist) |
| 2 | Speaking mode (speech input + text-to-speech) | B | — |
| 3 | Full-sentence translation with diff and self-grading | A, B (writing) | — |
| 4 | Mistakes log | A | 3 (reuses the diff) |

Suggested order: **1 → 2 → 3 → 4**.

## 1. Spaced repetition with a speed rule

### Why

Repeated retrieval at growing intervals is what moves an item into long-term memory. Today every session starts
from scratch, so items you already know take as much time as items you don't. A "correct but slow" answer still
fails you mid-conversation, so **an item is only promoted when it's correct *and* fast.**

### Algorithm (Leitner boxes)

| Box | Meaning | Next review after a fast, correct answer |
|---|---|---|
| 0 | New, never reviewed | → box 1, due in 1 day |
| 1 | | → box 2, due in 2 days |
| 2 | | → box 3, due in 4 days |
| 3 | | → box 4, due in 8 days |
| 4 | | → box 5, due in 16 days |
| 5 | "Mastered" | stays in 5, due in 32 days |

Each review records `correct` (boolean) and `responseMs`:

- **Correct and fast** (`responseMs <= threshold`): move to the next box (`box + 1`, capped at 5) and set `due_at = now + interval(newBox)`.
- **Correct but slow:** stay in the same box and set `due_at = now + 1 day`. You knew it, but you need it faster.
- **Wrong:** go back to box 1 (`box = 1`), set `due_at = now` (due again today) and increment `lapses`.
- "Correct" includes the accents-only verdict (`CORRECT_EXCEPT_ACCENTS`), matching what the sessions already do.

**Speed thresholds** are defaults the learner can change in Settings:

| Item | Mode | Threshold | How the time is measured |
|---|---|---|---|
| Vocabulary | Practice (typed) | 5 000 ms | From the prompt appearing to **Check** being pressed |
| Vocabulary | Study (flashcards) | 3 000 ms | From the card appearing to it being flipped. Only "Got it" counts as correct |
| Sentence | Fill the gap | 5 000 ms + 2 000 ms per extra gap | From the prompt appearing to **Check** being pressed |
| Sentence | Speaking (§2) | 4 000 ms | From the prompt appearing to recognition starting |

Measure the time on the client. Only the **first attempt** at an item in a session is posted. The in-session
"comes back at the end" repeats are still shown but don't count again.

Put the rules in one pure class, `ReviewScheduler.schedule(state, correct, responseMs, threshold, now)`, and test
it with a fixed `Clock`.

### Data model (`V4__review_state.sql`)

```sql
create table review_state (
    id               bigint generated by default as identity primary key,
    vocabulary_id    bigint references vocabulary (id) on delete cascade,
    sentence_id      bigint references sentence (id) on delete cascade,
    box              integer     not null default 0,
    due_at           timestamptz not null default now(),
    last_reviewed_at timestamptz,
    last_response_ms integer,
    reviews          integer     not null default 0,
    lapses           integer     not null default 0,
    check ((vocabulary_id is null) <> (sentence_id is null)),
    unique (vocabulary_id),
    unique (sentence_id)
);
create index idx_review_due on review_state (due_at);

create table review_log (            -- optional, useful for stats later
    id           bigint generated by default as identity primary key,
    vocabulary_id bigint references vocabulary (id) on delete cascade,
    sentence_id   bigint references sentence (id) on delete cascade,
    mode         varchar(20) not null,          -- STUDY | PRACTICE | CLOZE | SPEAK | TRANSLATE
    correct      boolean     not null,
    response_ms  integer     not null,
    reviewed_at  timestamptz not null default now()
);
```

Two nullable foreign keys, rather than a polymorphic `item_type` + `item_id`, keep `ON DELETE CASCADE` working.
A row is created lazily the first time an item is reviewed. Items with no row count as box 0 (new).

### API

| Method | Path | Body | Response |
|---|---|---|---|
| `POST` | `/api/reviews` | `{ "vocabularyId"? , "sentenceId"?, "mode", "correct", "responseMs", "thresholdMs" }` | `200` `ReviewState` |
| `GET` | `/api/courses/{courseId}/due?limit=50&newLimit=10` | — | `200` `DueItem[]` |
| `GET` | `/api/courses/{courseId}/progress` | — | `200` `[{ subjectId, boxes: [n0..n5], due }]` |

```json
// DueItem: the item is embedded so the client needs no extra requests
{ "type": "SENTENCE", "box": 2, "dueAt": "2026-11-05T08:00:00Z",
  "sentence": { "id": 4, "subjectId": 2, "text": "Ojalá {{pudiera}} ir…", "translation": "…", "hint": "poder", "explanation": "…", "position": 4 } }
{ "type": "VOCABULARY", "box": 0, "dueAt": null, "vocabulary": { "id": 9, "term": "ojalá", "translation": "I wish; hopefully", … } }
```

`/due` returns the overdue items first (oldest `due_at` first), then up to `newLimit` new items in learning-path
order (subject `position`, then item `position`), so new material comes in gradually.

### UI

- **Path screen (both apps):** a "Review · *n* due" card at the top that starts a mixed review session.
- **Review session:** a new `ReviewSession` holding a list of a sealed `ReviewItem` (`Word` | `Gap`). Vocabulary
  items are shown like Practice (type the translation) and sentences like Fill the gap. Reuse the existing
  composables by pulling the "one prompt" UI out of `PracticeScreen` and `ClozeScreen`.
- **Existing per-subject sessions** (Study, Practice, Fill the gap) also post reviews, so all practice counts.
- **Feedback:** "Correct, but slow (6.2 s)" when an answer misses the speed threshold, so the rule is visible.
- **Progress:** a small bar per subject on the path (share of items in boxes 4–5).
- **Settings:** the speed thresholds, the daily new-item limit and an "ignore speed" switch.

### Tests

- `ReviewScheduler`: every row of the table above, the box 5 cap, slow-but-correct, a lapse from box 5, and the
  per-gap threshold.
- `/due` ordering: overdue before new, the `newLimit` cap, and the learning-path order of new items.
- `ReviewSession` (Android): only first attempts are reported, and repeats still go to the end.

## 2. Speaking mode

### Why

Typing gives you time to think, while speaking doesn't. Saying the answer aloud under the speed rule is the
closest the app can get to conversation pressure. Both platforms have free speech recognition and text-to-speech.

### Android

**Speech input.** Start with the simplest option: launch `RecognizerIntent.ACTION_RECOGNIZE_SPEECH` through
`rememberLauncherForActivityResult`. It shows the system's speech UI and needs no `RECORD_AUDIO` permission.

```kotlin
Intent(RecognizerIntent.ACTION_RECOGNIZE_SPEECH).apply {
    putExtra(RecognizerIntent.EXTRA_LANGUAGE_MODEL, RecognizerIntent.LANGUAGE_MODEL_FREE_FORM)
    putExtra(RecognizerIntent.EXTRA_LANGUAGE, "es-ES")
    putExtra(RecognizerIntent.EXTRA_MAX_RESULTS, 5)
    putExtra(RecognizerIntent.EXTRA_PREFER_OFFLINE, true)
}
// result: getStringArrayListExtra(RecognizerIntent.EXTRA_RESULTS) — the n-best transcripts
```

Later, for a hands-free flow (no dialog, auto-start on each prompt), switch to `SpeechRecognizer` with
`RECORD_AUDIO`. Check `SpeechRecognizer.isRecognitionAvailable(context)`, and hide the mic button if it returns false.

**Grading speech.** Check **every** n-best transcript and keep the best verdict. Recognisers often put the right
form in result 2 or 3.

- *Vocabulary:* `AnswerChecker.check(transcript, translation)`.
- *Fill the gap, saying the whole sentence (recommended, because it's better speaking practice):* normalise the
  transcript into words. Then, for each gap in order, look for any of its alternatives as a run of whole words
  after the previous match. All gaps found means correct. Put this in a pure function next to `Cloze`
  (`Cloze.matchSpoken(text, transcript): List<Verdict>`) and test it.
- *Fill the gap, saying only the missing words:* check them as if they were typed.
- Recognisers write numbers as digits ("3" for "tres"). Avoid numbers in sentences for now, or add a small
  digit-to-word map for 0–20.

**Language.** Map the course language to a locale in the client: Spanish → `es-ES`, Catalan → `ca-ES`.
Add a `speech_locale` column to `course` only if the map becomes awkward.

**Text-to-speech.** Use `android.speech.tts.TextToSpeech` with `Locale("es", "ES")`. After every Check, speak
`Cloze.solved(sentence.text)` (or the vocabulary translation). A Settings toggle controls "read answers aloud".
Add a 🔊 button on the feedback card and a **Listen & repeat** button that plays the sentence and then opens
the mic, for shadowing.

**UI.** Add a mic button next to each answer field. A Settings switch, **Speak first**, makes the mic the
primary action and keeps the keyboard closed, with typing still available. Show what was recognised in the
feedback card ("Heard: …").

### Web

- **Recognition:** `window.SpeechRecognition || window.webkitSpeechRecognition` (Chrome and Edge), with
  `lang = 'es-ES'`, `maxAlternatives = 5` and `interimResults = false`. Hide the mic when it's unsupported
  (Firefox). Chrome sends the audio to Google's servers, which costs nothing but is worth a one-line note in
  Settings.
- **Text-to-speech:** `speechSynthesis.speak(new SpeechSynthesisUtterance(text))` with `lang = 'es-ES'`.
  Prefer a voice whose `lang` starts with `es-ES`, and fall back to any `es` voice.
- Put the speech helpers in `frontend/src/speech.js` and the spoken-sentence matcher in `cloze.js`, ported from
  the Kotlin version.

### Tests

`Cloze.matchSpoken`: an alternative in the middle of the sentence, gaps in the right order, extra filler words
("eh, si tuviera…"), capitalisation and punctuation in the transcript, and the best of several n-best results.

## 3. Full-sentence translation (writing)

### Why

Fill the gap tests one form in a sentence that's already written. Producing the **whole** sentence from English
is what writing (and speaking) actually needs.

### Content

No new table: a `Sentence` with a `translation` is already a translation exercise.

- **Prompt:** `sentence.translation` (English).
- **Model answer:** `Cloze.solved(sentence.text)`.
- **Accepted answers:** every combination of the gap alternatives (cartesian product, capped at 32). For example,
  `Si {{fuera/fuese}} tú, no {{diría}} nada.` accepts two sentences.
- Optional later: an `alternatives text` column (one full alternative sentence per line) for genuinely different
  wordings.

### Grading

1. If `AnswerChecker` accepts the answer against any accepted sentence, it's **correct** automatically.
2. Otherwise show a **word diff** between the answer and the closest accepted sentence (the one with the
   smallest edit distance). Use a token-level LCS on normalised words, which is fine at sentence length.
   Mark words as matching, missing (in the model only), extra (in the answer only), or accent-only differences.
3. The learner **grades themselves**: **Right** (a valid alternative wording), **Nearly** (a small slip) or
   **Wrong**. For the session, Right and Nearly count as done and Wrong goes to the back. For spaced repetition
   (§1), Right counts as correct, Nearly as "correct but slow" (no promotion), and Wrong as wrong.

Put the diff in pure code: `TextDiff.kt` and `frontend/src/diff.js`, each returning
`[{ word, kind: 'same' | 'missing' | 'extra' | 'accent' }]`. Test it: a reordered word, a missing article, an
accent-only change, and an empty answer.

### UI

- A new mode, **Translate**, next to Fill the gap, enabled when at least one sentence has a translation.
  The routes are `TranslateRoute(subjectId)` and `/subjects/:id/translate`.
- The prompt card shows the English, with a multi-line text field below it. Show the hint only after the first
  wrong attempt, or not at all.
- The feedback card shows the diff, highlighted inline (missing words underlined in red, extra words struck
  through), then the model answer, the explanation and the three self-grade buttons. With §2 in place, add 🔊
  to the feedback card and a mic button for answering out loud.

## 4. Mistakes log

### Why

Mistakes you actually made (corrected by a tutor, a friend or an autocorrect) are the most relevant practice
material there is, and you remember them better because of where they came from.

### Data model (`V5__sentence_source.sql`)

A mistake becomes a `Sentence`, so it automatically appears in Fill the gap, Translate and the review queue.

```sql
alter table sentence add column source varchar(20) not null default 'MANUAL';  -- MANUAL | MISTAKE
alter table sentence add column wrong_version varchar(1000);                     -- what I actually said/wrote
alter table sentence add column created_at timestamptz not null default now();
```

Mistakes need a subject. The client offers the subjects of the current course, plus an "Errores" subject that it
creates on first use (category "Mis errores") through the existing endpoints. No special server logic is needed.

### API

- `SentenceRequest` / `Sentence` gain `source` and `wrongVersion` (both optional; `source` defaults to `MANUAL`).
- `GET /api/courses/{courseId}/sentences?source=MISTAKE`: all mistakes in a course, newest first, for a
  "My mistakes" list.

### UI

- **Quick entry:** an **Add mistake** action (a FAB on the path screen on Android, a button on the web). The form has:
  1. *What I said* (`wrong_version`).
  2. *Correct version*, prefilled with the wrong version for editing. **Mark differences** uses the diff from §3
     to wrap the changed words in `{{…}}` automatically, which the learner can then adjust.
  3. *Subject* (defaulting to the last one used), plus optional *translation* and *note* (stored as `explanation`).
- **Android share target:** add an `ACTION_SEND` `text/plain` intent filter, so text shared from a chat app opens
  Add mistake with *What I said* prefilled.
- **During practice:** when a sentence has a `wrong_version`, the feedback card shows "You once said: …", struck
  through.
- **My mistakes list:** newest first, filterable by subject, with a "Practise all" button that runs Fill the gap
  over them.

### Tests

The "mark differences" function: one changed word, a changed word plus an inserted word, nothing changed (no
gaps, so saving is blocked), and a change at the start or end of the sentence.
